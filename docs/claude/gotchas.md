# Gotchas — Vending Machine POC

> Full detail behind the one-line rules in [CLAUDE.md](../../CLAUDE.md)'s Critical Rules section.
> Read this when a one-liner isn't enough context to act safely.

- **`.cluster.env` state file:** Makefile targets write runtime values (VPC ID, IAM ARNs, table names) here. Other targets `source` it. If targets fail with undefined vars, run `make get-cluster-info` or `make extract-iam-roles`.
- **Namespace is `default`, NOT `vm-apps`:** All production deployments use `-n default`. The `vm-apps` namespace exists but is not used for FortiFlex services.
- **Submodule = read-only:** `apps/fortiflex-marketplace/` is a git submodule of `fortigate-marketplace`. NEVER edit code there — always edit in the original repo, push, then `git pull` inside the submodule.
- **Terraform service discovery:** `arch/registry/main.tf` scans `apps/*/values.yaml` to auto-create ECR repos. The `name` field in `values.yaml` MUST match the desired ECR repo name.
- **IRSA pattern:** DynamoDB access requires: (1) Terraform creates role with OIDC trust, (2) role ARN exported to `.cluster.env`, (3) Helm `--set` annotates ServiceAccount, (4) pod auto-discovers creds.
- **sed-based config patching:** `make configure-sa` injects IAM role ARNs into `arch/sa.yml` via sed before `kubectl apply`. Fragile if YAML structure changes.
- **Helm retry with backoff:** ALB Controller install uses exponential backoff (up to 8 attempts) to handle transient CRD/API failures.
- **AWS SSO expiry:** Credentials expire every 8–12 hours. Re-auth: `AWS_PROFILE=our-eks aws sso login`, then refresh kubeconfig.
- **Compose DynamoDB Local:** Backend uses `AWS_ENDPOINT_URL_DYNAMODB=http://dynamodb:8000` in compose. From host, use `http://localhost:8000`.
- **Build args for frontends:** Submodule frontends need `VITE_BACKEND_HOST` passed as a build arg in compose to embed the correct backend URL at build time.
- **`kubectl rollout restart` does NOT apply `values.yaml`/Helm chart changes** — it only re-pulls the current image under the existing Deployment spec. Any change to `apps/<app>/values.yaml` (containerPort, securityContext, resources, env, etc.) needs `helm upgrade`, not just a restart. Caught live 2026-09-01: a `containerPort` bump (80→8080) sat un-applied after a restart, causing a 502 until `helm upgrade` actually ran.
- **`podSecurityContext.runAsNonRoot: true` requires an explicit numeric `runAsUser`/`runAsGroup`** in `apps/charts/shared/values.yaml` — without it, the kubelet can't resolve a Dockerfile's named `USER` (`appuser`, `node`) to a UID without running the container, and refuses to start it at all (`CreateContainerConfigError: cannot verify user is non-root`). Chart default is `1000` (matches every app's Dockerfile except `vm-poc-frontend-fortiflex`, which runs nginx's built-in uid 101 — overridden in that app's own `values.yaml`). Any new non-root Dockerfile must either use uid 1000 or add its own `podSecurityContext.runAsUser` override.
- **`fortiflex-marketplace-fortiaigate` K8s Secret now holds 4 keys**, not just `FORTIAIGATE_API_KEY`: `SESSION_SECRET`, `SAML_SP_PRIVATE_KEY`, `SAML_SP_CERT` were added via `kubectl patch` (2026-09-01, security remediation) — the name is now a misnomer, kept for continuity rather than a disruptive rename. `envFromSecret: fortiflex-marketplace-fortiaigate` in `vm-poc-backend-fortiflex-marketplace/values.yaml` mounts all four.
- **NetworkPolicy is chart-wide default-on** (`apps/charts/shared/templates/networkpolicy.yaml`) — default-deny ingress per pod, opt out per-app with `networkPolicy.enabled: false`. The ALB (`target-type: ip`) sends traffic straight to the pod IP from its own ENIs, and kubelet health probes come from the node IP — neither is a cluster pod, so neither is expressible as a `podSelector`. Both are covered by one `ipBlock` on the VPC CIDR (`networkPolicy.vpcCIDR`, default `10.0.0.0/16`) instead, auto-added whenever `ingress.enabled` or `healthCheck.enabled` is true. In-cluster pod-to-pod callers go in that app's own `networkPolicy.allowFrom: [<app label>, ...]`. Egress is left unrestricted by design (`egressEnabled: false`) — enumerating every external API each app calls is separate, higher-risk work.
- **`VMPOCAccessRole`/cross-account Helm deploy access is NOT Terraform/IaC-managed anywhere in this repo** — it's a manual `aws` CLI procedure in `README.md`. The old `AmazonEKSEditPolicy` association granted pod exec/attach/port-forward cluster-wide (worse than its originally-documented "broad Secret read"); `arch/vmpoc-helm-deployer-rbac.yaml` is the narrower replacement (namespace-scoped Role, no pod exec/attach/port-forward) — apply it via `kubectl apply` after `aws eks create-access-entry` per the updated README procedure, not via `associate-access-policy`. Note: Helm's default Secret-backed release storage means this narrower Role still needs Secret CRUD in-namespace — documented as an accepted residual tradeoff, not fully closed.
